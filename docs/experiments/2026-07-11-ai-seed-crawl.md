# 実証ログ: AI web 集約による 1 件シードの実効性

実施日: 2026-07-11
目的: concept.md の「コールドスタート / AI シードの実効性」論点を、机上から
実地に落とす。AI による web 集約で 1 件のキャンプ場情報をどこまで構造化して
埋められるか、出典が付くか、無名サイトで何が起きるかを検証する。

## 方法

- 対象 2 件を対比: 人気サイト(氷川キャンプ場)と無名サイト(小沢山荘キャンプ場)
- 各項目を「基本情報(当たり前品質)」と「差別化・実測 6 軸」に分け、値・出典URL・
  確認日・確信度・種別(客観/主観/実測)を 1 項目ずつ記録
- エリアは都心近郊(奥多摩・檜原村)を仮置き。実エリアで再実行する際の比較基準

### 重大な環境制約

本実行環境では **WebFetch が egress ポリシーにより全ホスト CONNECT 403**
(`connect_rejected`)で、ページ本文を 1 件も取得できなかった。値はすべて
**WebSearch のスニペット由来**。したがって:

- 確認日(ページ更新日)が取得できず、鮮度保証が付かない
- 緯度経度など「本来は地図 API で機械取得できる」項目も落ちた

→ 「無名ゆえの限界」と「フェッチ環境の限界」は切り分けが必要。今回の結果は
**本文フェッチなしの下限値**であり、本番のフェッチ可能な経路ではより埋まる。

## 結果サマリ

| | A: 氷川(人気) | B: 小沢山荘(無名) |
|---|---|---|
| 基本情報 | 10/10 | 約 4.5/10 |
| 差別化 6 軸 | 5.5/6 | 実質 0/6(所要時間のみ) |
| 出典URL | 100% | 埋まった項目には付くが項目自体が乏しい |
| 主観軸の質 | 複数ソース一致で暫定値に使える | 入力ソース 0 件で生成不能 |

### A: 氷川キャンプ場(人気)で埋まらなかった項目

- サイト実寸(㎡): フリーサイトで区画割なし・非公表
- 地面の水はけ: 低確信
- 地面の硬さ: **ソース間で矛盾**(硬く鍛造ペグ必須 vs 緩く抜けやすい)。
  単一値化は危険で「レンジ + 場所注記」で持つべき実例

### B: 小沢山荘キャンプ場(無名)の埋まり方

- 埋まった: 名称・住所・電話・大まかな営業期間(行政・地図・電話帳インフラ由来)
- 埋まらない(運用情報): 料金・予約・IN/OUT・定休・公式URL(公式サイト不在)
- 全滅(体験 6 軸): 地面・実寸・トイレ清潔感・混雑度。訪問者の一次記述が 0 件
- 例外: 所要時間のみ地理座標から演繹して充填

「無名」判断根拠: なっぷ・hinata・じゃらん・ブログ・口コミの全チャネルで
個別ページ/レポートが 0 件。痕跡が住所インデックスと村 PDF に限られる。

## 結論(concept.md 6 節・11 節に反映済み)

1. **埋まり方は web 露出量で 3 層に断絶する**: ①レジストリ層(無名でも埋まる)
   / ②運用情報層(公式サイト有無で明暗) / ③体験層=差別化軸(UGC ゼロで全滅)。
   例外は所要時間(座標から演繹)。
2. **AI 集約は「公開済み情報の再集約」で、無から一次観測は生めない**。無名施設の
   差別化軸は原理的に空白 → 電話取材・現地訪問という非 Web 入力が必須。
3. **AI シードは有効(下限値として心強い)**: 悪条件(スニペットのみ)でも人気
   サイトは基本 10/10・6 軸 5.5/6。
4. 設計含意: 出典種別・確認日を項目ごとに保持し空欄は「未確認」表示 / 主観軸は
   レンジ + 出典 + 場所注記 / 本文フェッチ可能なクロール経路が要る。

## 次アクション
