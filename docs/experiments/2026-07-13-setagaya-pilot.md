## 3 大学び

1. **「充足率」でなく「裏取り本数(確信度)」を指標にすべき**。5 軸は 1 本でも
   ブログがあればセルが埋まるので見かけ 96%。だが人気=複数ブログ一致で高確信、
   無名(Do-c)=単一ブログで低確信。→ フォーマットに裏取り本数/確信度が必須。
2. **人気 vs 無名の断絶は「埋まるか」でなく「信じてよいか」に出る**。無名の
   Do-c は電話番号すら web に無く(問い合わせフォームのみ)、営業期間欠落、
   5 軸は単一ブログ頼み。基本の欠落と主観軸の裏取り不能が同時に起きる。
3. **web で永久に埋まらない項目が特定できた**:
   - 緯度経度 → 住所からジオコーディング(収集でなく変換)
   - AC電源・営業期間・無名の電話/料金 → 電話が要る
   - 近隣コンビニ → 地図 API
   - トイレのきれいさ・地面の硬さ → web は参考、現地/電話で確定(実測は常にゼロ)

## 収集コストと 30〜50 件への外挿

- web 集約: 1 件あたり 2〜3 検索 → 30〜50 件で 約 90〜150 検索(数時間)
- ＋ 緯度経度は一括ジオコーディング(自動バッチ)
- ＋ 電話ラウンド 30〜50 本(AC電源・営業・無名の穴埋め、計 1.5〜2.5 時間)
- **結論: 「週末 1〜2 回分」でエリア最強の初期データが作れる規模。最大律速は
  実在するが趣味開発として回せる。**
- 403 回避に集約サイト(なっぷ/じゃらん/hinata)を主 source にすると効率↑だが
  更新遅れリスク。本文フェッチ可能なクロール経路は技術方針で別途詰める。

## フォーマットへの反映(→ 5.1 / CSV に反映済み)

- **足す**: 予約要否・予約方法 / ペット可否 / 直火・川遊び可否 / 裏取り本数

- **軸 5 個は妥当**。ただしトイレきれいさ・地面硬さは「web=参考、現地=確定」運用
