# 実データ収集パイロット: 近郊エリア 5 件

実施日: 2026-07-13
エリア: 都心から車 1.5〜2 時間の近郊ベルト。到達可能圏を「エリア」と定義。
目的: 5.2 の絞り込み 5 軸と 5.1 の収集フォーマットの実用性を実データで検証。
1 件あたりの収集コスト・充足率・埋まらない軸を測る。具体施設名は伏せる。

## 制約

WebFetch は公式・集約サイトで軒並み 403。有効な収集はほぼ WebSearch の
スニペット。実測(現地計測)値は現地未訪問のため全件ゼロ。

## 対象 5 件の内訳

人気サイト 3 件(ブログ・口コミ多数)+ 無名寄り 2 件(ブログが数本〜ほぼ無し。
うち 1 件は新規小規模)。人気→無名の断絶を見るための構成。

## 充足率(値あり率、5 件平均)

| ブロック | 充足率 | 弱点 |
|---|---|---|
| ①基本(7) | 約 69% | 緯度経度 0/5、営業期間 1/5、料金 3/5 |
| ②設備(6) | 約 57% | AC電源 1/5、近隣コンビニ 0/5 |
| ③5軸(5) | 見かけ 96% | 充足 ≠ 品質(下記) |

## 3 大学び

1. 「充足率」でなく「裏取り本数(確信度)」を指標にすべき。5 軸は 1 本でも
   ブログがあればセルが埋まるので見かけ 96%。人気=複数ブログ一致で高確信、
   無名=単一ブログで低確信。→ フォーマットに裏取り本数/確信度が必須。
2. 人気 vs 無名の断絶は「埋まるか」でなく「信じてよいか」に出る。無名施設は
   電話番号すら web に無い(問い合わせフォームのみ)ことがあり、基本の欠落と
   主観軸の裏取り不能が同時に起きる。
3. web で永久に埋まらない項目:
   - 緯度経度 → 住所からジオコーディング(収集でなく変換)
   - AC電源・営業期間・無名施設の電話/料金 → 電話が要る
   - 近隣コンビニ → 地図 API
   - トイレのきれいさ・地面の硬さ → web は参考、現地/電話で確定(実測は常にゼロ)

## 収集コストと 30〜50 件への外挿

- web 集約: 1 件あたり 2〜3 検索 → 30〜50 件で 約 90〜150 検索(数時間)
- ＋ 緯度経度は一括ジオコーディング(自動バッチ)
- ＋ 電話ラウンド 30〜50 本(AC電源・営業・無名施設の穴埋め、計 1.5〜2.5 時間)
- 結論: 「週末 1〜2 回分」でエリア最強の初期データが作れる規模。最大律速は
  実在するが趣味開発として回せる。

## フォーマットへの反映(→ 5.1 / CSV に反映済み)

- 足す: 予約要否・予約方法 / ペット可否 / 直火・川遊び可否 / 裏取り本数
- 分類変更: 緯度経度は「住所から自動生成」列へ。「実測」は現地調査フェーズ専用
- ラベル分離: トイレ様式(設備・客観)と トイレのきれいさ(主観)を分ける
- 軸 5 個は妥当。ただしトイレきれいさ・地面硬さは「web=参考、現地=確定」運用
