# ADR 0002: データは最初リポジトリ内のファイルで持ち、必要になったらデータベースに移す

ADR 0001 の「見送った案」にある「データはリポジトリ内のファイル」を見直す。

## 決定

キャンプ場のデータは、最初はリポジトリ内のファイル(TypeScript の型付き)で持つ。
データベース(PostgreSQL)は、必要になったときに入れる。

## 理由

- MVP の件数は 30〜50 件で、ファイルで十分に扱える。
- データベースを入れると、画面に何も出ないうちにアカウント・マイグレーション・
  接続設定・環境変数の準備が要る。まず詳細ページを作ってデータの持ち方を確かめたい。
- データの追加や修正が PR の差分に残り、どの値がいつ、どの出典で変わったかを追える。
- 数十件のファイルをデータベースに移す手間は小さい。

## 見送った案

| 案 | 見送った理由 |
|---|---|
| 最初から PostgreSQL(Supabase か Neon) | 今の件数では要らず、準備の手間が先に来る |

## 影響

- データを集めて整えるスクリプトは、データベースではなくファイルに書き出す。
- ユーザーに値を入れてもらう仕組みを作るとき、または件数が増えてファイルでは
  扱いにくくなったときに、データベースに移す。
