# ADR 0001: Next.js 1 つで作り、データを集めて整える仕組みは分ける

## 決定

Web アプリは Next.js 1 つで作り、画面とサーバー側の処理を持たせる。データを集めて
整え、データベースに入れる処理は、同じリポジトリの別の TypeScript スクリプトに
する。

## 理由

- データを集めて整える処理は、必要なときにまとめて動かせばよく、Web アプリに
  置く必要がない。独立したスクリプトで済む。
- 言語(TypeScript)と公開先(Vercel)が 1 つで済み、少ない手間で持続的に開発
  できる(concept.md 副目的①)。
- MVP にはユーザー投稿もログインもなく(mvp.md)、別のバックエンドを立てるほどの
  サーバー処理がない。

## 見送った案

| 案 | 見送った理由 |
|---|---|
| Next.js + Rails API | 集めて整える処理はスクリプトで足り、Rails の強み(バックグラウンドのジョブ・管理画面)を使う場面が少ない。言語と公開先が 2 つになる手間が残る |
| Next.js のみで、データはリポジトリ内のファイル | データを集めて増やしていく見込みがあり、データベースが要る |

## 影響

- Vercel には 1 回の処理時間に上限があるため、データを集める処理は手元か
  GitHub Actions で動かす。
- ユーザー投稿やログインを入れるとき、またはサーバー側の処理が重くなったときは、
  バックエンドを分けるかを見直す。
