# MVP スコープ

目的・課題・提供価値は [concept.md](concept.md) を参照。

## 対象範囲

最初は関東近郊の 30〜50 件に絞り、「このエリアなら一番詳しい」状態を作る。

## 入口

条件検索。絞り込み軸は少数で始める(軸が多いほど 1 件あたりの調査コストと実装が
膨らむため)。「対象ユーザーに役立つ × 既存サービスで探せない × データを集められる」
で選び、役割ごとに分ける。

**基本の絞り込み**

- 都心からの所要時間(決まった起点から経路を計算した、渋滞なしの目安)
- 車の横付け(オートサイト)可否

**このサービスならではの軸**

- 区画の広さ(㎡)
- 静かさに関わる事実: 静粛時間、グループ利用の可否、高速道路・国道・鉄道までの
  距離(キャンプ場の代表地点から地図データで計算した直線距離)

**詳細ページに出典付きで載せる(絞り込み軸にはしない)**

- 地面の種類、トイレの設備、総サイト数
- 売店・レンタル・風呂・近隣コンビニなど

**見送り**

地面の硬さ、トイレのきれいさ、携帯の電波。公開されている情報では値を埋められないため。

## データの持ち方

- キャンプ場は ID と座標で管理し、その下にサイトの種類を持つ。区画の広さと横付け
  可否はサイトの種類ごとに違うため、サイトの種類の値として持つ。
- 絞り込みでは、条件をすべて満たすサイトの種類が 1 つでもあるキャンプ場を出す。
- 値ごとに出典 URL・情報源の種類・調べた日を持つ。埋められない値は「未調査」とする。

## 画面構成(最小)

1. 検索ページ(絞り込み + 一覧)
2. キャンプ場詳細ページ(スペック表 + 地図)

## 体験原則

**使いやすくモダンなデザインにする**(concept.md 副目的②)。スマホで軽く速く、
迷わず絞り込める体験を目指す。既存サービスとの一番の違いは「他にない軸(区画の広さ・
静かさ)で絞り込めること」で、UI/UX はそれを使いやすく届ける役割。

## やらないこと(MVP では)

- 予約機能・料金比較
- 自由記述レビュー(比べにくい断片的な情報が増えるため、今後もやらない)
- ユーザー投稿の仕組み(認証・フォーム・モデレーション)。利用者がいない初期は
  意味がないため MVP では作らない
- レコメンド、横並び比較 UI
- 全国網羅
