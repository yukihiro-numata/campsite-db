# MVP スコープ

戦略・背景・決定記録は [concept.md](concept.md)、技術構成は [tech.md](tech.md) を参照。

## 入口

条件検索。絞り込み軸は 3〜5 個の少数精鋭で始める(軸が多いほど 1 件あたりの
調査コストと実装が膨らむため)。

## 画面構成(最小)

1. 検索ページ(絞り込み + 一覧)
2. キャンプ場詳細ページ(スペック表 + 地図)

## 体験原則

モバイルで軽く速く使えること。ただしモバイル操作性は差別化の主軸ではなく
**衛生要因**(あって当たり前で差別化にならない要素): 操作性への不満は小さく、
本当の不満は予約の取りにくさ・情報の鮮度・信頼。既存大手(なっぷ/hinata/sotoshiru)も使いやすいアプリを持つため
**"使いやすさ"では戦わない**。UX は「他にない軸(程度・実測・中立)で絞り込める
× サッと使える」のセットで入口の取っかかりにとどめる(技術は tech.md)。

## やらないこと(MVP では)

- 予約機能・料金比較
- 自由記述レビュー(比較を壊す断片が増えるため恒久的にやらない)
- ユーザー投稿インフラ(認証・フォーム・モデレーション)。無人の初期は
  無意味なため MVP では作らない。ただし構造化 UGC を後段で開けるよう、
  データモデルには最初から投稿を載せられる余地を残す(D6 / concept.md
  「データ戦略」)
- レコメンド、横並び比較 UI
- 全国網羅
