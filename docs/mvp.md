# MVP スコープ

目的・課題・提供価値は [concept.md](concept.md)、技術構成は [tech.md](tech.md) を参照。

## 対象範囲

最初は自宅周辺エリアの 30〜50 件に絞り、「このエリアなら一番詳しい」状態を作る。

## 入口

条件検索。絞り込み軸は少数で始める(軸が多いほど 1 件あたりの調査コストと実装が
膨らむため)。「対象ユーザーに役立つ × 既存サービスで探せない × データを集められる」
で選んだ次の 5 つ:

1. 都心からの所要時間
2. 車の横付け(オートサイト)可否
3. トイレのきれいさ
4. 地面の種類と硬さ(ペグの刺さりやすさ)
5. 静かさ・混み具合

売店・レンタル・風呂・近隣コンビニなどは詳細ページに表示し、絞り込み軸にはしない。

## 画面構成(最小)

1. 検索ページ(絞り込み + 一覧)
2. キャンプ場詳細ページ(スペック表 + 地図)

## 体験原則

**使いやすくモダンなデザインにする**(concept.md 副目的②)。スマホで軽く速く、
迷わず絞り込める体験を目指す。既存サービスとの一番の違いは「他にない軸(程度・実測)で
絞り込めること」で、UI/UX はそれを使いやすく届ける役割(技術は tech.md)。

## やらないこと(MVP では)

- 予約機能・料金比較
- 自由記述レビュー(比べにくい断片的な情報が増えるため、今後もやらない)
- ユーザー投稿の仕組み(認証・フォーム・モデレーション)。利用者がいない初期は
  意味がないため MVP では作らない。ただし構造化 UGC を後から受け付けられるよう、
  データモデルには最初から投稿を載せられる余地を残す
- レコメンド、横並び比較 UI
- 全国網羅
