# コンセプトドキュメント

## 1. 目的

趣味で長く育てられる Web サービスを個人開発する。

- 個人開発として継続できる規模で運営する
- 検索・地図・データモデリング・インフラなど新しい技術を学びながら開発する
- GitHub で公開する前提で、通用する品質を目指す

## 2. 課題仮説

### 仮説

キャンパーが比較したい「行ってみないと分からない情報」は、既存サービスでの
扱われ方で 2 つに分かれる。

- **有るか・どんな種類か(以下「有無・種類」)**: 例——トイレは有るか/水洗か、
  地面は砂利か芝か、オートサイトか、近くにコンビニがあるか。Yes/No や
  カテゴリで表せるため、hinata などが既にタグ化している。
- **どれくらいか(以下「程度・実測」)**: 例——トイレのきれいさ、地面の硬さ
  (ペグの刺さりやすさ)、静かさ、混み具合、区画の広さ(㎡)。量や度合いの情報で、
  ブログ・YouTube・口コミに散らばって横断比較できない。ここが空白。

→ この**「程度・実測」を比較できる軸に構造化**できれば差別化になる。

### 根拠1: 競合は「有無・種類」止まり

| サービス | 主目的 | 構造化済み(=差別化にならない) |
|---|---|---|
| なっぷ | 予約 + 検索(最大級) | エリア/料金/予約可否/サイトタイプ/電源/風呂/ペット/様式トイレ。サイト広さは「100㎡以上」の二値どまり |
| hinata スポット | 検索(メディア起点) | 上記に加え **地面の種類/24時間管理/近隣コンビニ・スーパー/車乗り入れ/穴場** までタグ構造化 |
| TAKIBI | 情報メディアのみ(予約は 2024/9 終了) | 予約・検索の競合としては実質消滅 |
| Google マップ | 地図 + 口コミ | 実地スペックは非構造化。ユーザーが口コミ件数から混雑度を自力推定 |

最も進んだ hinata でも「有無・種類」のタグ止まりで、「程度・実測」を軸に持つ
社は無い。

### 根拠2: ペインは実在

地面・騒音・トイレ・広さ・買い出しで失敗談や回避策が多層的に見つかる。
「ブログ/YouTube を漁る」が選び方の王道として指南され、それを集約する二次
サービス(トイレ専用 DB・動画レビュー等)まで生まれている。

### 空白地帯(どこにも構造化されていない = 差別化余地)

1. 地面の"質"(ペグの刺さりやすさ・硬さ・水はけ) ※種類は hinata が構造化済
2. サイトの実寸(㎡)での範囲検索
3. トイレの"きれいさ"(様式は構造化済だが清潔感はない)
4. 混雑度の実測(時期別・実データ)
5. 静かさの"度合い"(穴場の二値のみ)
6. 都心/主要都市からの所要時間での絞り込み

## 2.5 競合の全体像と勝ち筋

hinata や既存の集約サービスが、これだけのニーズがあるのに「決定版」に
なれていない理由と、そこから見える勝ち筋。

### なぜ誰も決定版になれていないか(共通の失敗パターン)

1. **単一軸の袋小路**(トイレなう=トイレだけ / キャンプイズム=動画だけ):
   深いが狭く「まず候補を絞る」入口を取れず、横断比較もできない
2. **一次データを持たない集約は無力**(WOM CAMP=他人ブログへのリンク集):
   Google・大手メディアに埋もれ、名前で探してもらえない
3. **B2B 掲載課金モデルの構造矛盾**(キャンプイズム=施設が制作費負担):
   払った施設しか載らず網羅不能、かつ利益相反でネガ実測が載らない
4. **鮮度維持コストで失速**: トイレ・地面・電波は変化が速く供給が止まると陳腐化
5. **薄いカバー率でのローンチ**: 数百件では「載ってない」体験が定番化を殺す
6. **市場は淘汰局面**: 予約特化の TAKIBI ですら 2024/9 撤退

なっぷ(約5,900件)も hinata(約7,000件)も、網羅で勝つ代わりに「程度・実測」を
犠牲にしている。ここが空白。

### 中立性は強みだが、参入障壁ではない

我々の立場は「予約送客や施設からの掲載課金に依存しない中立」。ただしこれは
他社が真似できない壁ではない。送客で稼ぐ Hipcamp(米)も、ホスト手数料を
取りながら 👍😐👎 の評価や騒音・清潔さのネガ情報を構造化して公開しているし、
なっぷ自身も多軸の星評価と低評価の口コミを載せている。つまり「送客・掲載課金で
稼ぐと施設のネガ情報を出せない」わけではなく、大手もやろうと思えばできる
(裏取り: `docs/experiments/2026-07-11-hypothesis-verification.md`)。

確かなのは「"程度・実測"(静かさ・混雑・電波・トイレの汚れ 等)を比較できる軸で
持つ国内サービスが今は無い」こと。だから我々の強みは"壁"ではなく、次の 4 つ:

- (a) 実在する空白がまだ埋まっていない
- (b) 大手は網羅・送客・EC に注力していて、程度・実測まで手が回っていない
- (c) 実測データは集めるのが高コストで主観的(自分で試して確認済み)
- (d) 施設からお金を取らないのでバイアスがない

趣味の個人開発(1 節)なら、真似されない完全な守りは要らず、これで十分。ただし
Hipcamp のような資本が本気で参入すれば追いつかれうる。なお「施設からお金を
取らない」方針は、同じく非課金で運営する The Dyrt やマンションノートが
「ネガ情報も含む構造化比較が事業として成立する」実例として裏づける(D8 / 6 節)。

### 勝ち筋(一言)

> 予約送客・掲載課金に依存しない**中立**の立場で、キャンプ場の「程度・
> 実測情報」(地面の硬さ・静かさ・混雑・電波・傾斜・実寸…)を**横断比較**
> できるようにする。**ネガ情報が載ることこそ資産**。全国を薄く狙わず、
> まず特定エリア/ペルソナに絞り、そこで一番に思い出される存在になる。

補強方針:
- 差別化の核は**「主観★」でなく「方法論のある実測指標」**(多軸★だけなら
  hinata が低コストで追随可能。実測まで踏み込めば網羅モデルと相性が悪く
  追随しにくい)
- **体験(モバイル操作性)は差別化の主軸ではなく衛生要因**(あって当たり前で
  良くても差別化にならない要素)。詳細は mvp.md・tech.md。
- **鮮度を最重要項目として扱う**(各データに「最終実測日」。一括更新に弱い
  大手の逆を突く)
- カバーは**軸とエリアを絞る**(薄いカバー率ローンチの罠を回避)

### 避けるべき罠

単一軸に閉じる / B2B 掲載課金に寄せ中立性を捨てる / リンク集に堕す /
鮮度設計を怠る / 薄いカバーで全国に広げる。

### 新規リスク

- **sotoshiru(スペースキー運営)が未調査**。写真+UGC レビュー+スポットの
  アプリで構造が我々に近く、hinata より警戒すべき可能性(9 節)
- **市場の淘汰局面**。ただし 1 節の通り趣味の個人開発のため
  「事業存続」のハードルは低く、致命傷ではない

## 4. 収集項目と絞り込み軸

**「収集項目」と「絞り込み軸」は別物**。収集項目は各キャンプ場について DB に
持つ全情報で広い。絞り込み軸(4.2)はそのうち検索で絞れるようにする少数精鋭で
狭い。例: 住所や料金は「収集するが絞り込み軸にはしない(詳細ページに表示する
だけ)」。両者を混同すると「絞り込み軸=集める情報の全部」と誤解する。

### 4.1 収集項目(各キャンプ場について DB に持つ情報)

差別化になる情報(下表③)だけでなく、**名称・住所などの当たり前品質(①)も
必須**。収集項目は 4 カテゴリに分ける。

| カテゴリ | 例 | 位置づけ |
|---|---|---|
| ① 基本情報(当たり前品質・必須) | 名称 / 住所 / 緯度経度 / 電話 / 公式URL / 営業期間・シーズン / 定休日 / IN・OUT 時刻 / **予約要否・予約方法** / 料金レンジ | **MVP 必須**。地図・詳細ページの土台。無いと MVP が成立しない |
| ② 設備・サービス(有無中心) | サイトタイプ(区画/フリー/オート/コテージ) / AC 電源 / 風呂・シャワー・温泉 / 売店・レンタル / ゴミ捨て / **ペット可** / **直火・川遊び可否** / トイレ様式 / 近隣コンビニ・スーパー・風呂 | 競合も構造化済。差別化にはならないが"当たり前品質"として必要 |
| ③ 差別化・実測(ペインの空白地帯) | 地面の質(硬さ・水はけ) / サイト実寸㎡ / トイレのきれいさ / 静かさの度合い / 混雑度 / 車横付け / 都心からの所要時間 | 2 節の空白地帯。サービスの芯 |
| ④ メタ情報(各項目に付随) | 出典種別(キュレーション/AI/ユーザー) / 出典URL / 確認日 / **裏取り本数** / 確信度 | 5 節データ戦略と対応。鮮度・信頼性の担保 |

各カテゴリの「埋まりやすさ」は大きく異なる(5 節)。運用ルール:

- **緯度経度は「収集」でなく住所からの自動生成(ジオコーディング)**列に分類。
- **「実測」種別は web フェーズでは常に空欄**になるため現地調査フェーズ専用。
- 品質指標は「充足率」でなく **「裏取り本数(確信度)」**とする(5 軸は 1 本の
  ブログでもセルが埋まるため)。フォーマットは `docs/data/collection-template.csv`。

### 4.2 絞り込み軸(②③ から選抜した 5 軸)

「初心者に刺さる × 差別化になる × 埋められる」で 5 軸を選抜。

| # | 軸 | 分類 | 埋め手 |
|---|---|---|---|
| 1 | 都心からの所要時間 | アクセス | AI/地図(易) |
| 2 | 車横付け(オートサイト)可否 | 安心・有無 | AI(易) |
| 3 | トイレのきれいさ | 差別化・程度 | **web=参考 / 現地=確定** |
| 4 | 地面の種類 + 硬さ(ペグ) | 差別化・程度 | 種類=AI / 硬さは **web=参考 / 現地=確定** |
| 5 | 静かさ・混雑(穴場度) | 差別化・程度 | UGC/AI 暫定 |

- 売店・レンタル・風呂・近隣コンビニ等は**収集はするが絞り込み軸にはしない**
  (詳細ページ表示。4.1 の区別通り)。

## 5. データ戦略

差別化の芯である「程度・実測」情報(地面の硬さ・トイレのきれいさ・
静かさ・混雑度)は、1 人の手動収集では埋めにくい。これを **AI シード →
構造化 UGC で補完** の 3 層で解く。

### 3 層構造

1. **AI シード層**: web 上の公開情報から"下書き"を作り、DB を埋める。客観軸
   (所要時間・地面の種類・トイレ様式・実寸)は埋めやすく、主観軸(きれいさ・
   静かさ・混雑)も"暫定値+出典"で埋める。→ 空欄を減らし、次段の投稿ハードルを下げる
2. **ユーザー確認・修正層(後段)**: 訪問者が「合ってる/違う」をワンタップで
   補正。0 からの空欄記入ではなく確認・修正にすることで投稿が集まりやすく、
   主観軸を実体験で上書きして鮮度・実測を担保する
3. **集約・モデレーション層**: 複数報告を集約(平均化)、出典・確認日・報告
   件数を保持。スパム/荒らしへの簡易対策

### 埋まり方は web 露出量で層ごとに断絶する

AI 集約は「既に公開された情報の再集約」で、無から一次観測は生めない。よって
埋まり方はサイトの web 露出量で分かれる(実証: 人気サイトと無名サイトの
2 件比較。`docs/experiments/2026-07-11-ai-seed-crawl.md`)。

| 層 | 中身(≒4.1 のカテゴリ) | 支えるもの | 無名でも埋まるか |
|---|---|---|---|
| ① レジストリ層 | 名称・住所・電話・大まかな営業期間 | 自治体・地図・電話帳インフラ | ○ 埋まる(無名でも 8〜9 割) |
| ② 運用情報層 | 料金・予約・IN/OUT・定休・公式URL | 施設自身の公式サイト | △ 公式サイト有無で明暗(無名=落ちる) |
| ③ 体験層(=差別化軸) | 地面・実寸・トイレのきれいさ・静かさ・混雑 | 訪問者の UGC(ブログ・口コミ) | ✕ UGC ゼロなら全滅 |
| (例外) 所要時間 | — | 緯度経度から演繹 | ○ 常に埋まる(施設固有でない) |

人気サイトは基本情報も差別化軸もほぼ埋まるが、無名サイトは基本情報が半分・
差別化軸(③)がほぼ空になる。無名の③は AI・UGC どちらでも埋まらず、電話取材・
現地訪問という**非 Web 入力が必須**。AI の役割は「何が空いているかの可視化 +
電話導線を残す」まで。

### 原則

- **出典種別(キュレーション/AI/ユーザー)・確認日・報告件数を項目ごとに持つ**。
  空欄は正直に「未確認」表示する(無名は空欄だらけになる前提)。
- **主観軸は単一の断定値でなく「レンジ + 出典 + 場所注記」**で持つ(ソース間で
  値が矛盾しうるため)。
- **まず自分で埋め、後から投稿で補う**: 投稿の仕組みは初期(データも利用者も
  いない)では無意味。初期 30〜50 件は自分で埋め切って「エリア最強」を作り、
  価値と流入を作ってから投稿を開く(D7 / mvp.md)。
- 蓄積された「構造化された実測 UGC」は競合(hinata でもレビューしか無い)が
  持たない蓄積で、時間が経つほど効いてくる。
- 情報源: 公式サイト、自治体・観光情報、ブログ・SNS・YouTube、衛星写真、
  実地訪問、および将来のユーザー投稿。

### 信頼性の留意

- 掲載するのは事実データで、項目ごとに出典 URL を紐づける(他者コンテンツの
  丸ごと転載はしない)。中立比較の信頼性の土台。
- LLM 抽出は誤帰属・捏造がありうるため、出典で検証可能にする。

## 6. 収益化

広告収益を第一候補とする(Google AdSense / Amazon アソシエイト /
楽天アフィリエイト)。将来的にキャンプ用品・予約サービス連携を検討。

**制約(D8 と一体)**: 収益化は**非独占のアフィリエイト送客・広告**に留め、
**施設からの掲載課金は取らない**。掲載課金や特定予約先への送客依存は、
レビュー・比較を施設寄りに歪め「ネガ実測も載る中立性」を損なう(2.5 節)。
中立性は参入障壁ではないが我々の芯であり、収益と衝突したら中立性を
優先する。
