# コンセプトドキュメント

最終更新: 2026-07-07

## 1. 目的

趣味で長く育てられる Web サービスを個人開発する。

- 個人開発として継続できる規模で運営する
- 新しい技術を学びながら開発する
- GitHub で公開し、ポートフォリオとして通用する品質を目指す

AI を前提としたサービスにはしない。プロダクト設計・検索・地図・
データモデリング・インフラを重視する。

## 2. 課題仮説

既存サービス(なっぷ・TAKIBI・hinata 等)は予約と口コミが中心で、
キャンパーが本当に比較したい「行ってみないと分からない情報」は
口コミやブログに断片的に埋もれている。初心者は結局ブログや YouTube を
何時間も漁ってキャンプ場を決めている。

→ 構造化されたスペックデータで検索・比較できる場所を作れば差別化できる。

※ 競合のライブ調査は未実施。実施後にこの節を更新する。

## 4. MVP スコープ(案)

### 入口

条件検索。絞り込み軸は 3〜5 個の少数精鋭で始める(軸が多いほど
1 件あたりの調査コストと実装が膨らむため)。

### 画面構成(最小)

1. 検索ページ(絞り込み + 一覧)
2. キャンプ場詳細ページ(スペック表 + 地図)

### やらないこと(MVP では)

- 予約機能・料金比較
- ユーザー投稿・レビュー
- レコメンド、横並び比較 UI
- 全国網羅

## 5. 絞り込み軸(提案・未決定)

初心者ターゲットのため「安心系」を主軸に、競合にない「差別化軸」を
1〜2 個混ぜる構成を提案する。

| 分類 | 候補 | 備考 |
|---|---|---|
| 安心系(主軸) | トイレのきれいさ / 売店・レンタル有無 / 管理人常駐 / 近隣の風呂・コンビニ | 初心者の最重要関心事 |
| 差別化軸(1〜2 個) | 車横付け可否 / 地面の種類(ペグの刺さりやすさ) / 静かさ | 競合が構造化していない情報 |
| アクセス系 | 都心からの所要時間 | 検索条件として汎用性が高い |

→ データ収集フォーマット作成時に確定する。

## 6. データ戦略

- 手動キュレーションを基本とする(D3)
- 情報源: 公式サイト、自治体・観光情報、ブログ・SNS、衛星写真、実地訪問
- スマホから入力できるフォーマット(スプレッドシート)を用意する
- 出典と確認日を項目ごとに記録し、鮮度を担保する
- 将来: ユーザー投稿による補完を検討(MVP 後)

## 7. 収益化

広告収益を第一候補とする(Google AdSense / Amazon アソシエイト /
楽天アフィリエイト)。将来的にキャンプ用品・予約サービス連携を検討。

## 8. 技術方針

| レイヤ | 選定 | 状態 |
|---|---|---|
| フロントエンド | Next.js (App Router)。SEO 重視 | 候補 |
| バックエンド | Ruby on Rails API | 候補 |
| DB | PostgreSQL + PostGIS | 候補 |
| 地図 | MapLibre + OpenStreetMap(Google Maps 非依存) | 候補 |
| ストレージ | S3 互換(Cloudflare R2) | 候補 |
| インフラ | Vercel / Fly.io / Supabase | 候補 |

実装開始時に ADR として確定させる。
