# docs/ ドキュメント作成ルール

`docs/` 配下のドキュメントを書く・直すときのルール。

## 1. 結論ファーストで、冗長な経緯を書かない

- 結論を先に簡潔に書く。検討履歴・取り消し線・済み項目は本文に残さず
  git に任せる(未決リストは開いているものだけ)。
- 同じ結論・数値を複数の節で繰り返さない(1 か所を正典に、他は参照)。
- 日付やメタな注記(「〜時点」「〜で合意」など)を書かない。
- **例外**: 経緯が結論の根拠になっているものは残す
  (例:「当初 X と考えたが証拠 Y で反証し Z に修正」、証拠 → 結論の表)。

## 2. 平易な単語を使う(読者はエンジニア)

- IT・エンジニアに通じる用語(MVP, SEO, ADR, UGC 等)はそのまま使ってよい。
- 避ける: 和文に生埋めの英単語、定訳のない英語フレーズ。
- **比喩・抽象的な言い回しを避け、一読で意味が取れる具体語にする**
  (例: 堀/モート → 参入障壁)。
- 専門用語を残すときは初出に一言の注を付ける。
- 用語をそろえる。他のサービスは「既存サービス」と書き、「競合」とは書かない。

## 3. 決めたことだけを、実際の理由で書く

- まだ決めていないことを決まったように書かない
  (例: データの集め方、スクリプトの言語、データベースの製品)。
- 判断の理由には実際に考えた理由を書き、あとから理由を付け足さない。
